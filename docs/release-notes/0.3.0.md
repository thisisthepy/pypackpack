# pypackpack 0.3.0

The body of the `v0.3.0` GitHub Release (the release that `publish-pypi.yml` uploads to PyPI). Same
shape as the 0.2.0 release.

---

The CPython 3.15t release: the commands the guide documents (`ppp python install 3.15t <target>` among
them) work on what PyPI installs.

## Install

```shell
uv tool install pypackpack    # puts pypackpack and ppp on PATH
uv tool upgrade pypackpack    # from 0.2.0
ppp --version                 # PyPackPack version 0.3.0
uvx pypackpack --help         # or run it without installing
```

One wheel per platform carries the command line as a GraalVM native image: macOS 11+ on Apple silicon, Linux x86_64 and aarch64 (glibc), Windows x86_64. There is no source distribution on purpose: building needs a JDK and GraalVM.

## Changed (read before upgrading)

- Python distributions are CPython 3.15t only: `3.15` and `3.15t` both mean the free-threaded `3.15.0t` on desktop. 3.14.7, 3.13.0 and the desktop 3.15.0 GIL builds are no longer offered (#72, #76). Android and iOS keep python.org's 3.15.0 GIL builds until python-multiplatform #163.
- `ppp init` creates a standalone project (`uv init --bare --no-workspace`). In 0.2.0, running it below an unrelated `pyproject.toml` made the new project a member of that project's uv workspace and wrote `[tool.uv.workspace]` into the other file. Use `ppp package add` to add a package to a ppp workspace.

## What's new since 0.2.0

- `ppp python install 3.15t <target>`: `python install`, `use`, `find` and `uninstall` accept the free-threaded `t` suffix (`3.15t`, `3.15.0t`). Wheel tags come from the target interpreter (#76).
- `ppp --version`, `ppp -v` and `ppp v` print the version, like `ppp version`.
- `ppp build <package> source [binary|fat|single|patch]` and `ppp build <package> resource` bundle from the command line (#81).
- `native` / `mixed` build levels for the `resource` bundle on macOS, Linux host and Android arm64, through the compile slot (#20).
- Meson builds extensions for `abi3t` against the project's `.venv` interpreter, and the `resource` bundle warns about dependencies that would run the app with the GIL (#72).
- Rust crates through a Cargo backend (maturin + PyO3, `abi3t`) for the host, Android and iOS (#92, #94).
- `ppp deploy code single|fat` publishes wheels to PyPI with `uv publish` (#90).
- Windows x86_64: markers use the `AMD64` machine name uv 0.13.6 evaluates (#107); uv older than 0.13.6 is refused there, and the uv pypackpack downloads is 0.13.6 (#109).
- Deleting a directory no longer follows symbolic links out of it (#96).
- Library: install named requirements into an existing venv (#40). The `packpack` library keeps its own version (0.1.0, `gradle.properties`) and its own `packpack-v*` release.
- Guide: https://thisisthepy.github.io/pypackpack/ (getting started now starts from `uv tool install pypackpack`).

## Not yet

The `binary` bundle, `deploy` to FastTrack and ResourceHub, code push, and C/C++ cross-compiling through Meson are planned. See the guide's status page.
