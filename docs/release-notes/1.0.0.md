# pypackpack 1.0.0

The body of the `v1.0.0` GitHub Release (the release that `publish-pypi.yml` uploads to PyPI). Same
shape as the 0.4.x releases.

---

The first stable release. What 1.0 covers, what stays partial and what comes after it is recorded in
`docs/SPEC.md` (*1.0 scope*): every item marked `implemented` there has a test in this repository.

## Install

```shell
uv tool install pypackpack    # puts pypackpack and ppp on PATH
uv tool upgrade pypackpack    # from 0.4.x
ppp --version                 # PyPackPack version 1.0.0
uvx pypackpack --help         # or run it without installing
```

One wheel per platform carries the command line as a GraalVM native image: macOS 11+ on Apple silicon, Linux x86_64 and aarch64 (glibc), Windows x86_64 (also runs on Windows on ARM under x64 emulation). There is no source distribution on purpose: building needs a JDK and GraalVM.

The Kotlin library is `org.thisisthepy.python.multiplatform:packpack:1.0.0` (it was `0.1.0`); `toolchain` moves to it in the same release.

## New since 0.4.1

- The Cargo backend builds a Windows target on a machine of that architecture: on Windows on ARM, where `ppp` runs as x64 under emulation, `--target aarch64-pc-windows-msvc` builds with maturin against the target Python from `ppp python install 3.15t aarch64-pc-windows-msvc` and gives a `win_arm64` wheel. A Windows target on a machine of another architecture is still refused: there is no cross toolchain (#150).

## After 1.0 (owner's decision)

FastTrack deploy (`deploy code binary|patch`) and code minification stay refusals with a message. Nuitka, Cython and Lpython are not build backends: TypedPython compiles (the `native` / `mixed` levels).
