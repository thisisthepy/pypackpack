# pypackpack 0.4.1

The body of the `v0.4.1` GitHub Release (the release that `publish-pypi.yml` uploads to PyPI). Same
shape as the 0.4.0 release.

---

Windows compatibility patch release for 0.4.0: portable GraalVM native images (`-march=compatibility`)
and Windows `.pyd` `abi3`/`abi3t` wheel tag detection.

## Install

```shell
uv tool install pypackpack    # puts pypackpack and ppp on PATH
uv tool upgrade pypackpack    # from 0.4.0
ppp --version                 # PyPackPack version 0.4.1
uvx pypackpack --help         # or run it without installing
```

One wheel per platform carries the command line as a GraalVM native image: macOS 11+ on Apple silicon, Linux x86_64 and aarch64 (glibc), Windows x86_64. There is no source distribution on purpose: building needs a JDK and GraalVM.

## Fixed since 0.4.0

- GraalVM native images now build with `-march=compatibility` (`packpack/build.gradle.kts`), so distributed binaries run on baseline CPUs and Windows ARM64 x64 emulation without requiring AVX/AVX2/BMI/FMA (#147).
- Wheel bundlers (`single`, `fat`, `patch`) now inspect `[tool.ppp.rust]` `abi` (`abi3-py3<minor>` / `abi3t-py3<minor>`) for untagged Windows `.pyd` extensions (`<name>.pyd`), producing `cp313-abi3` / `cp315-abi3.abi3t` wheel tags instead of falling back to `cp315-cp315t` (#147).
