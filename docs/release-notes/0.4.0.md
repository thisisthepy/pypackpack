# pypackpack 0.4.0

The body of the `v0.4.0` GitHub Release (the release that `publish-pypi.yml` uploads to PyPI). Same
shape as the 0.3.0 release.

---

Mixed Cargo and library-wheel release: single-package repositories, Python source-root discovery, full
PEP 621 wheel metadata, configurable PyO3 ABI / Cargo features, Linux `manylinux_2_17` cross-builds,
and free-threaded 3.15t on Android and iOS.

## Install

```shell
uv tool install pypackpack    # puts pypackpack and ppp on PATH
uv tool upgrade pypackpack    # from 0.3.0
ppp --version                 # PyPackPack version 0.4.0
uvx pypackpack --help         # or run it without installing
```

One wheel per platform carries the command line as a GraalVM native image: macOS 11+ on Apple silicon, Linux x86_64 and aarch64 (glibc), Windows x86_64. There is no source distribution on purpose: building needs a JDK and GraalVM.

## Changed (read before upgrading)

- Android and iOS Python distributions are now free-threaded CPython 3.15.0t (`thisisthepy/python-multiplatform` `cpython-3.15.0t-mobile`), matching desktop. The 3.15.0 GIL mobile builds are no longer offered (#124).
- The WASM target triple is renamed to `wasm32-emscripten` and its wheel platform tag to `emscripten_4_0_19_wasm32` (CPython sysconfig / PEP 783 spelling, #82).

## What's new since 0.3.0

- Single-package projects without `[tool.uv.workspace]`: `build`, `deploy`, and per-target dependency commands resolve the root project by `[project].name`, root directory name, or `.`, and workspace members also match by `[project].name` (#129).
- Python source roots and package data: `Meson`, `Cargo`, and `resource` bundling discover packages under `[tool.ppp].python-dir`, `src/main`, `src`, `python`, `<package>/python`, and the package root. Meson preserves non-`.py` package data files and treats `.c`/`.cpp` files as extension modules only when listed in `[tool.ppp].c-extensions` or (when omitted) when their name starts with `_` or their source references `PyInit_`, `PyModExport_`, or `Python.h` (`c-extensions = []` disables C/C++ extension scanning, #130, #144).
- Meson `limited_api`: derived from `[project].requires-python` (`>=3.<minor>` / `==3.<minor>`) or `[tool.ppp.rust]` `abi` (`abi3-py3<minor>` / `abi3t-py3<minor>`), defaulting to `'3.15'` (#142).
- Wheel bundlers (`single`, `fat`, `patch`): full PEP 621 `[project]` metadata rendering into `<dist-info>/METADATA` (`Metadata-Version: 2.4`, including `license-files` under `<dist-info>/licenses/`), `instant`/`bytecode`/`mixed`/`native` build levels, and extension-derived wheel tags (`abi3`, `abi3.abi3t`, `cpXYt`) (#131).
- Cargo backend `[tool.ppp.rust]` configuration: inline tables and package-level defaults for PyO3 ABI mode (`abi3t-py315`/`abi3t`, `abi3-py3<minor>`, `cp3<minor>[t]`), Cargo `features`, and `default-features = false` (`--no-default-features`) across host, Android, and iOS (#135).
- Cargo backend Linux cross-build: `x86_64` / `aarch64` `manylinux_2_17` and `manylinux_2_28` targets build via `uv tool run --from maturin==1.15.0 --with ziglang maturin build --zig` (#138). Windows builds stay host-only on Windows runners; WASM waits for `python-multiplatform#175`.
- Guide: https://thisisthepy.github.io/pypackpack/ updated for single-package layouts, `[tool.ppp]` / `[tool.ppp.rust]`, Linux cross-builds, and wheel bundlers (#141).

## Not yet

The `binary` bundle, `deploy` to FastTrack and ResourceHub, code push, WASM compilation, and C/C++ cross-compiling through Meson are planned. See the guide's status page.
