Known issues알려진 문제

  • #49 — aarch64 markers on Linux and Android never match, so those targets get no per-package dependencies.#49 — Linux, Android 의 aarch64 마커가 맞지 않아 그 타깃에 패키지별 의존성이 설치되지 않습니다.
  • #50 — --python-version cannot be passed through to uv.#50 — --python-version 을 uv 로 넘길 수 없습니다.
  • pypackpack --version, -v and a bare help are not wired; use ppp version and --help.pypackpack --version, -v, 대시 없는 help 는 연결되지 않았습니다. ppp version 과 --help 를 쓰세요.
  • init cannot take targets; add them afterwards with target add.init 은 타깃을 받지 못합니다. 나중에 target add 로 추가하세요.
  • ppp sync ignores the venv path, and python use does not clean package build/ directories.ppp sync 는 venv 경로를 무시하고, python use 는 패키지의 build/ 를 정리하지 않습니다.
  • Several commands find the project through user.dir rather than an explicit directory.몇몇 명령은 명시적 디렉터리가 아니라 user.dir 로 프로젝트를 찾습니다.
  • The downloader holds a whole archive in memory; .tar.xz and PAX/GNU long names are not read.다운로더가 아카이브 전체를 메모리에 둡니다. .tar.xz 와 PAX/GNU 긴 이름은 읽지 않습니다.

Contributing기여하기

Changes go intent → spec → test → code: a behaviour change starts in docs/SPEC.md, its test is written and seen failing, then the code makes it pass. implemented always cites a test in this repository.

변경은 의도 → 스펙 → 테스트 → 코드 순서입니다. 동작 변경은 docs/SPEC.md 에서 시작하고, 테스트를 먼저 써서 실패를 본 뒤, 코드로 통과시킵니다. implemented 는 언제나 이 저장소의 테스트를 근거로 듭니다.

./gradlew :packpack:test     # the library
./gradlew :cli:test          # the command line
python3 docs/guide/check_guide.py    # this site
